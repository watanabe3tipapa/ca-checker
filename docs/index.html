CA Certificate Checker

このツールは何のためにあるのか

ca-checker は、証明書を発行・配布するためのツールではありません。いま自分の環境が信頼している証明書が、本当に信頼してよい状態かを確認するための「信頼の点検ツール」です。

証明書は、ファイルやストアに置いてあるだけでは安全ではありません。有効期限が切れていないか、弱い署名アルゴリズムを使っていないか、発行者とのつながりが正しいか、失効していないか。これらを確認して初めて、証明書は「信頼の鎖」として機能します。ca-checker は、その鎖を人間にも機械にも扱いやすい形で可視化します。

why

信頼を「なんとなく」で終わらせない

OS の信頼ストアには、日々の開発や運用で意識されないまま多数のルート CA と中間 CA が入っています。期限切れや未信頼の証明書が紛れていても、通常の業務は動いてしまうことがあります。ca-checker は、その見えないリスクを一覧できる状態にします。

visibility trust-store
who

開発者・運用・セキュリティ担当へ

ローカル環境の TLS エラーを切り分けたい開発者、証明書の期限を事前に把握したい運用担当、弱い署名や失効を確認したいセキュリティ担当。GUI と CLI のどちらからでも、同じ検証エンジンを使えます。

developer sre security
how

期限・署名・連なり・失効をまとめて確認

有効期限、弱い署名アルゴリズム、ルートからリーフまでのチェーン、CRL / OCSP による失効状態を確認します。結果はステータス、検証メッセージ、JSON として出力でき、CI の終了コードにも利用できます。

expiry chain revocation

ca-checker が答えるのは、次の4つの問いです。

  1. この証明書は、いつまで有効か

    有効期間の開始前・期限切れ・期限間近を判定します。期限警告日数は 7 / 30 / 90 / 180 日から選べ、設定ファイルにも保存できます。

  2. この署名は、十分に強いか

    MD5 や SHA-1 など、現在では弱いとされる署名アルゴリズムを検出します。

  3. この証明書は、信頼の起点までつながっているか

    ルート CA・中間 CA・リーフ証明書の連なりを rustls-webpki で検証します。自己署名証明書や未信頼のルートも区別して表示します。

  4. この証明書は、失効していないか

    証明書が公開している CRL Distribution Point と OCSP Responder を使って失効状態を確認します。有効・失効・不明を区別し、取得できなかった理由も表示します。

利用場面ca-checker でできること
ローカル開発TLS エラーの原因が期限切れ・未信頼・失効のどれかを切り分ける
日々の運用OS 信頼ストアを一覧し、期限間近の証明書をデスクトップ通知で把握する
リリース前チェックverify --revocation を CI に組み込み、異常時は終了コード 1 で止める
セキュリティ確認弱い署名アルゴリズムや失効済み証明書を洗い出す
調査・学習証明書のフィールド、チェーン、CRL / OCSP の応答を画面と CLI で確認する

できないこと: 秘密鍵の管理、証明書の発行、HSM / スマートカードの操作、CT ログの照会は行いません。また、失効確認は証明書が公開している CRL / OCSP エンドポイントに依存するため、ネットワークや提供元の状態によって「不明」になることがあります。ca-checker は専門的な PKI 運用を置き換えるものではなく、日々の確認を手早くするための補助ツールです。

検証ステータス

証明書は次のいずれかの状態で分類されます。Valid と ExpiringSoon が正常扱いです。

ステータス意味正常
Valid有効期限内で、チェーン検証に成功はい
ExpiringSoon警告日数以内に期限切れ（デフォルト 30 日）はい
Expired有効期限が切れているいいえ
NotYetValid有効期間開始前いいえ
UntrustedRoot信頼チェーンを構築できないいいえ
SelfSigned自己署名かつ信頼ストアに未登録いいえ
WeakSignatureMD5 / SHA-1 など弱い署名アルゴリズムいいえ
RevokedCRL / OCSP により失効が確認されたいいえ
RevocationUnknown失効確認を実行したが、判定できなかったいいえ
Errorその他の検証エラーいいえ

使い方

  1. ビルドする

    Rust 1.85 以上が必要です。macOS で GPUI をビルドする場合は Xcode の DEVELOPER_DIR を指定してください。

    git clone https://github.com/watanabe3tipapa/ca-checker.git
cd ca-checker
export DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer
cargo build --workspace

  2. GUI を起動する

    OS の信頼ストアを読み込み、ダッシュボードを開きます。Import から証明書ファイルやフォルダを追加でき、Settings で期限警告日数・通知・失効確認モードを変更できます。

    cargo run -p app

    失効確認を有効にしたら、証明書の詳細画面で「Check revocation」を押します。Terminal タブではローカルシェルを起動できます。

  3. CLI で検証する

    OS の証明書一覧、ファイルの詳細、チェーン検証、失効確認、通知、設定ファイルの表示を実行できます。

    # 設定ファイルを初期化する
cargo run -p cert_cli -- config --init

# OS 信頼ストアの一覧
cargo run -p cert_cli -- list-os

# 証明書ファイルの詳細
cargo run -p cert_cli -- inspect certificate.pem

# ルートを明示してチェーン検証 + CRL / OCSP 失効確認
cargo run -p cert_cli -- verify leaf.pem \
  --chain intermediate.pem \
  --trust root.pem \
  --revocation both

# 期限切れ・期限間近をデスクトップ通知する
cargo run -p cert_cli -- notify

# ディレクトリを再帰スキャン
cargo run -p cert_cli -- scan /path/to/certs --json

    設定ファイルの場所は ~/.config/ca-checker/config.toml です。--config PATH で別のファイルを指定できます。

現在の制限

  • ネットワーク経由の証明書取得（TLS ハンドシェイク）は未実装
  • GUI のファイル選択は対応済みですが、ウィンドウへのドラッグ＆ドロップは未対応
  • OCSP の nonce 検証は未対応
  • Windows は未対応
  • wterm は Web 専用のため、GUI 内では GPUI ネイティブの PTY ターミナルを使用
  • GPUI は pre-1.0 のため、アップグレード時に API 変更が発生する可能性あり
